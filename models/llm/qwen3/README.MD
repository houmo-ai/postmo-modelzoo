# Qwen3(通义千问3)

本示例展示如何把Qwen3模型量化和编译，部署到后摩鸿途芯片的设备上。

[TOC]

## 1 模型说明

本例使用的模型实现来源于[https://modelscope.cn/models/Qwen/Qwen3-8B](https://modelscope.cn/models/Qwen/Qwen3-8B)。

## 2 快速开始

目前Qwen3模型仅提供python脚本编译方式。芯片模型只能在linux环境下量化和编译。

### 2.1 获取模型和数据

通过get_model脚本下载模型，可通过参数选择下载原始模型、量化模型或芯片模型。

如果需要自己量化，可选择下载原始模型和wikitext2数据集，下载后的模型存放在qwen3-8b目录：

```bash
python3 get_model.py --type raw
```

如果仅编译芯片模型，可选择下载量化模型，下载后的模型存放在`output/$HOUMO_TARGET/hmquant`目录（注意相同模型会覆盖，请自行保存）：

```bash
python3 get_model.py --type quant
```

如果仅查看演示结果，可选择下载芯片模型，下载后的模型存放在当前目录（注意相同模型会覆盖，请自行保存）：

```bash
python3 get_model.py --type hmm
```

也可以直接下载以上所有模型和数据集（注意相同模型会覆盖，请自行保存）：

```bash
python3 get_model.py
```

### 2.2 量化

量化需要使用GPU，并在宿主机安装与CUDA12.2兼容的CUDA和驱动。启动docker时将GPU映射到docker内，并指定可用的GPU ID，显存需要达到40GB以上，空闲内存需要达到100GB以上。参考命令：

```bash
docker run -it --gpus all --pid=host -w /hmdd -v $PWD:/hmdd --shm-size 64g harbor.houmo.ai/toolchain/release:vx.y.z-ubuntu20.04-py39-x86.64 /bin/bash
```

进入docker后source环境变量，并进入`/hmdd/models/llm/qwen3`目录，执行ptq.py脚本。默认的prefill和decode上下文长度分别为256和8192，可通过ptq.py中的prefill_shape和cache_len参数修改。不同编译模式下支持的上下文长度组合为：
| cores | batch | prefill | decode |
| ----- | ----- | ------- | ------ |
| 4     | 1     | 256     | 8192   |
| 2     | 1     | 256     | 8192   |

```bash
source env.sh
cd /hmdd/models/llm/qwen3
python3 ptq.py
```

量化完成的模型存放在`output/$HOUMO_TARGET/hmquant`目录：

```bash
.
|-- decoder
|-- prefill
|-- quant_embedding.pt
`-- weight.npy
```

### 2.3 编译

将量化模型编译为在芯片上运行的模型。执行脚本：

```bash
python3 build.py
```

编译好的模型存放在当前目录，包括2个文件：
qwen3_prefill.hmm
qwen3_decode.hmm

### 2.3 演示

Qwen2模型使用python API进行演示

1. 将编译好的模型放在当前目录，同时将对应量化模型的`quant_embedding.pt`文件放在量化模型目录下，也可通过demo中的`EMBEDDING_PATH`变量指定位置

2. 执行脚本，推理完成将输出性能结果。

```bash
python3 demo.py
```

### 2.4 一键评估

以上步骤可以通过test.sh脚本一键执行：

```bash
bash test.sh
```

存算一体技术（Compute-in-Memory, CIM）是一种将存储和计算功能集成在同一硬件单元中的技术，其核心思想是通过减少数据在存储器和计算单元之间的传输，提升计算效率和能效。以下是其主要优势：

---

### **1. 提升能效（Energy Efficiency）**
- **减少数据搬运**：传统冯·诺依曼架构中，数据需要在存储器和计算单元之间频繁搬运，导致高能耗。存算一体通过将计算直接集成到存储单元中，显著减少数据移动，从而降低能耗。
- **低功耗设计**：例如，使用新型存储器（如相变存储器、忆阻器）时，其计算过程的能耗远低于传统CMOS计算单元，尤其适合低功耗场景（如物联网、移动设备）。

---

### **2. 提高计算速度（Speed）**
- **并行计算能力**：存算一体架构允许存储单元同时执行计算任务，例如在矩阵运算中，存储器中的数据可以直接用于计算，无需等待数据传输，从而显著提升速度。
- **适用于高并发场景**：在人工智能（如神经网络训练和推理）和大数据处理中，存算一体技术能高效处理大规模并行计算任务。

---

### **3. 降低延迟（Latency）**
- **减少数据传输瓶颈**：传统架构中，数据需要从存储器（如DRAM）传输到计算单元（如CPU/GPU），导致延迟。存算一体通过将计算嵌入存储器，直接在存储单元中完成计算，避免这一瓶颈。
- **适合实时应用**：例如，自动驾驶、实时视频处理等对延迟敏感的场景，存算一体技术能提供更快速的响应。

---

### **4. 优化资源利用（Resource Utilization）**
- **硬件资源共享**：存算一体技术通过整合存储和计算资源，减少对独立计算单元和存储器的需求，从而优化硬件资源的利用效率。
- **降低硬件成本**：在某些应用场景（如边缘计算），通过存算一体设计，可以减少对高性能计算单元的依赖，降低成本。
